6. Arsitektur Sistem & Kebutuhan Non-Fungsional (NFR)
Pengembangan sistem akan dilakukan menggunakan basis Laravel (v10/v11). Mengingat arsitektur sangat bergantung pada tier gratis (Hobby/Free Tier), berikut adalah batasan dan mitigasi arsitekturnya:

6.1. Deployment & Backend (Vercel Hobby Tier)

Kendala: Vercel Hobby memiliki batas waktu eksekusi fungsi maksimal 10 detik.

Mitigasi: Segala proses berat (seperti AI API calls, generation PDF bukti transaksi, atau upload file) tidak boleh dilakukan secara sinkron. Gunakan arsitektur asinkron (misalnya, webhook response cepat lalu processing berjalan di background atau client-side).

6.2. Manajemen Database (TiDB Cloud Free)

Kendala: Keterbatasan jumlah koneksi konkuren pada tier gratis.

Mitigasi: Wajib mengaktifkan Connection Pooling (misal: PDO::ATTR_PERSISTENT di Laravel) agar serverless function Vercel tidak membuat koneksi baru setiap kali diakses, yang dapat menyebabkan Connection Exhaustion.





6.3. Manajemen Media (Cloudinary Free)

Mitigasi Storage: Dilarang mengunggah file gambar/dokumen melewati backend Laravel. Gunakan metode Direct-to-Cloud Upload dari frontend langsung ke Cloudinary untuk menghemat alokasi memori dan menghindari timeout Vercel.

6.4. Sistem Notifikasi (OneSignal Free)

Digunakan untuk mengirim push notification real-time ke perangkat Tim Marketing/Developer saat ada pesanan baru masuk atau pembayaran tervalidasi.

Strategi Pengujian Kinerja (Stress & Load Testing dengan k6)

Untuk memastikan limit gratisan dari Vercel dan TiDB tidak tumbang saat trafik tinggi, wajib dilakukan uji beban menggunakan skrip otomatis k6:

Skenario Simulasi Order Masuk: Mensimulasikan 50-100 Virtual Users (VUs) yang melakukan checkout bersamaan untuk menguji Connection Pooling TiDB.

Skenario Webhook Payment: Menembak endpoint callback pembayaran secara bertubi-tubi untuk memastikan Vercel merespons di bawah 2 detik agar tidak di-blacklist oleh Payment Gateway.

Threshold (SLA): 95% dari seluruh request harus memiliki waktu respons di bawah 2.5 detik (p-95 < 2500ms), dan error rate harus di bawah 1%.

10.1. Mitigasi Serverless Timeout (Vercel Hobby Tier) 

Tantangan: Vercel menetapkan batas eksekusi ketat (10-15 detik) untuk Serverless Functions pada akun Hobby. Proses berat seperti pemanggilan API AI untuk pembuatan PRD atau pengolahan laporan finansial berisiko mengalami Request Timeout (RTO). 

Strategi Mitigasi:

Asynchronous Processing (202 Accepted): Setiap permintaan yang membutuhkan pemrosesan AI tidak akan ditunggu secara sinkron. Server langsung mengembalikan respons HTTP 202, memasukkan tugas ke antrean (queue/background task), dan membebaskan fungsi Vercel agar tidak memicu timeout. 

Chunking: Proses pemrosesan data besar wajib dipecah menjadi beberapa bagian kecil (chunks) yang dieksekusi secara bertahap menggunakan bantuan pemicu cron eksternal atau berkala. 

10.2.  Manajemen Database Terdistribusi (TiDB Cloud Free) 

Tantangan: Karakteristik serverless pada Vercel cenderung membuka koneksi database baru pada setiap request, yang dengan cepat dapat menghabiskan kuota batas koneksi (Connection Exhaustion) pada TiDB Cloud tier gratis. 

Strategi Mitigasi:

Persistent Connection Pooling: Konfigurasi driver database Laravel wajib memaksa penggunaan PDO::ATTR_PERSISTENT atau memanfaatkan proxy koneksi bawaan TiDB untuk menjaga koneksi tetap hidup dan dapat digunakan kembali (reused) antar request. 

Isolasi Beban Kerja (HTAP): Memanfaatkan kemampuan arsitektur hybrid TiDB untuk memisahkan kueri transaksional cepat (OLTP) dengan kueri analitik berat dari AI (OLAP) guna menghindari penurunan performa pada tabel inti.

12. Keamanan, Webhook Idempotensi, & Validasi Signature 
12.1.  Penanganan Idempotensi Webhook pada Serverless Vercel 

Karena sifat jaringan internet dan retry policy dari sistem pembayaran yang agresif, endpoint webhook berisiko menerima payload yang sama berulang kali. 

Strategi Mitigasi (Idempotency Key): Setiap request wajib menyertakan X-Idempotency-Key atau menggunakan kombinasi unik dari order_id + payment_status. Nilai ini disimpan sementara di dalam database atau cache. Jika request dengan key yang sama terdeteksi kembali, sistem langsung mengembalikan status sukses tanpa memproses ulang transaksi. 

12.2.  Contoh Implementasi Middleware Validasi Signature (Laravel) 

Untuk memastikan bahwa data callback benar-benar dikirim oleh Midtrans (bukan manipulasi pihak ketiga), tim engineering wajib menerapkan pengecekan Signature Key: 

PHP
namespace App\Http\Middleware;
use Closure;use Illuminate\Http\Request;use Symfony\Component\HttpFoundation\Response;
class VerifyMidtransSignature{
    public function handle(Request $request, Closure $next): Response
    {
        $payload = $request->getContent();
        $orderId = $request->input('order_id');
        $statusCode = $request->input('status_code');
        $grossAmount = $request->input('gross_amount');
        $serverKey = config('services.midtrans.server_key');

        // Rekonstruksi SHA512 Signature standar Midtrans
        $localSignature = hash("sha512", $orderId . $statusCode . $grossAmount . $serverKey);

        if ($localSignature !== $request->input('signature_key')) {
            return response()->json(['message' => 'Invalid Signature Key Callback denied.'], 403);
        }

        return $next($request);
    }
}

12.3. Kebijakan Keamanan & Kepatuhan Data (UU PDP Compliance) 

Gunakan metode Blind Index (Hashing HMAC-SHA256 dengan salt rahasia pada kolom terpisah, misal phone_number_hash) untuk kebutuhan pencarian data unik, sedangkan kolom aslinya tetap dienkripsi tanpa constraint unik.

Penyimpanan Data Sensitif: Seluruh data pribadi klien (nama, email, log komunikasi) wajib dienkripsi saat disimpan di TiDB Cloudmenggunakan algoritma AES-256-GCM. 

Kebijakan Retensi Log Finansial: Log transaksi finansial wajib dikunci dan disimpan secara utuh selama minimal 5 tahun untuk kebutuhan audit internal dan kepatuhan hukum, terpisah dari log aktivitas debug aplikasi biasa.

Masalah: Vercel Hobby mematikan proses dalam waktu maksimal 10 detik. Kita tidak bisa menjalankan perintah daemon php artisan queue:work secara terus-menerus di Vercel. 

Solusi Konkret:

Set driver antrean Laravel ke database (QUEUE_CONNECTION=database) di TiDB Cloud. 

Buat satu endpoint khusus yang aman: /api/v1/internal/queue-runner?token=RAHASIA_WAVE.
Di dalam endpoint tersebut, jalankan perintah: Artisan::call('queue:work --once --max-time=7'); (Berhenti di detik ke-7 agar fungsi Vercel tidak mengalami timeout).

Gunakan layanan pihak ketiga gratis seperti Cron-Job.org untuk menembak endpoint tersebut setiap 1 menit sekali guna memproses antrean pembuatan PRD oleh AI di latar belakang.

Detail Langkah-Langkah Sistem:

Fase Pra-Order: Klien berdiskusi dengan AI Chat di web. Jika sepakat, klien mengisi form checkout dan menyertakan link GitHub publik. 

Fase Validasi AI: Backend mengirim data form + link GitHub ke Gemini API untuk dianalisis: "Apakah paket yang dipilih (misal: Paket Web Landing Page) sesuai dengan kompleksitas target sistem yang diinginkan klien?" Jika tidak sesuai, AI memberikan rekomendasi penyesuaian paket di layar sebelum pembayaran dilakukan. 

Fase Transaksi: Klien memilih opsi bayar (DP 30% atau Full). Laravel menembak API Midtrans untuk mendapatkan snap_token. 

Fase Webhook Pasca-Bayar: Midtrans mengirim sinyal sukses ke /api/v1/payments/callback. Sistem langsung memperbarui status di database TiDB, memicu OneSignal untuk menyalakan notifikasi di HP Team Marketing & Developer, dan memasukkan tugas pembuatan PRD ke antrean database.

import http from 'k6/http';import { check, group, sleep } from 'k6';
export const options = {
  scenarios: {
    // Skenario 1: Simulasi lonjakan trafik pengguna menjelajahi web dan bertanya ke AI
    browsing_and_chat: {
      executor: 'ramping-vus',
      startVUs: 0,
      stages: [
        { duration: '30s', target: 30 }, // Naik dari 0 ke 30 user dalam 30 detik
        { duration: '1m', target: 30 },  // Bertahan di 30 user selama 1 menit
        { duration: '15s', target: 0 },  // Turun kembali ke 0
      ],
      gracefulRampDown: '15s',
    },
    // Skenario 2: Simulasi lonjakan transaksi checkout simultan (Stress Test Inti)[cite: 1]
    heavy_checkout: {
      executor: 'per-vu-iterations',
      vus: 15, // 15 user melakukan checkout serentak[cite: 1]
      iterations: 2,
      maxDuration: '2m',
    },
  },
  thresholds: {
    'http_req_duration{name:CheckoutAPI}': ['p(95)<3000'], // Checkout wajib di bawah 3 detik agar tidak memicu limit Vercel[cite: 1]
    'http_req_failed': ['rate<0.02'], // Tingkat kegagalan sistem maksimal harus di bawah 2%[cite: 1]
  },
};
export default function () {
  const BASE_URL = 'https://wave-projects-center-id.vercel.app/api/v1';

  // GROUP 1: Simulasi Hit Landing Page & Paket Layanan[cite: 1]
  group('01_Browsing Paket & Portofolio', function () {
    const res = http.get(`${BASE_URL}/packages`);
    check(res, {
      'status is 200': (r) => r.status === 200,
    });
    sleep(1);
  });

  // GROUP 2: Simulasi Submit Transaksi Pemesanan[cite: 1]
  group('02_Proses Checkout Pesanan Baru', function () {
    const url = `${BASE_URL}/orders/checkout`;
    const payload = JSON.stringify({
      client_name: `Automated Test VU-${__VU}`,
      client_email: `dev.test_${__VU}@waveprojects.id`,
      client_whatsapp: '081234567890',
      project_purpose: 'Saya ingin membuat sistem e-commerce produk kopi lokal terintegrasi kasir.',[cite: 1]
      package_id: 'pkg_fullstack_mvp',
      github_url: 'https://github.com/ariyas/public-dummy-repo',[cite: 1]
      payment_choice: 'DP_30'[cite: 1]
    });

    const params = {
      headers: {
        'Content-Type': 'application/json',
        'X-Idempotency-Key': `k6-stress-key-uuid-${__VU}-${__ITER}`,
      },
      tags: { name: 'CheckoutAPI' },
    };

    const res = http.post(url, payload, params);
    check(res, {
      'Order berhasil dibuat (201)': (r) => r.status === 201,
      'Snap Token Midtrans Terbaca': (r) => r.json().data.snap_token !== undefined,
    });
    sleep(2);
  });
}

Glosarium Istilah Teknis (Glossary)

Mengingat PRD Wave Projects Center.ID ini sangat spesifik dalam mengakali infrastruktur serverless free-tier, glosarium sangat penting agar tim non-teknis (seperti Tim Marketing atau Kasir) dan tim developer baru memiliki bahasa serta pemahaman yang sama.

MVP (Minimum Viable Product): Versi produk paling awal yang memiliki fitur minimal namun sudah cukup matang untuk diluncurkan ke pasar.

Serverless Timeout: Batas waktu maksimal eksekusi fungsi di serverless cloud (seperti Vercel Hobby yang membatasi hingga 10–15 detik) sebelum koneksi diputus paksa.

Connection Pooling: Teknik menjaga koneksi database tetap hidup dan dapat digunakan kembali untuk menghemat kuota limit koneksi pada database (TiDB Cloud).

Idempotency (Kekal-tetap): Jaminan keamanan sistem di mana sebuah request (misal webhook pembayaran) yang ditembak berkali-kali secara tidak sengaja hanya akan diproses tepat satu kali oleh database.

Webhook / Callback: Mekanisme pengiriman data otomatis dari satu sistem (Midtrans) ke sistem lain (Laravel Vercel) secara real-time segera setelah suatu peristiwa terjadi.

VU (Virtual Users): Istilah pengguna tiruan dalam alat pengujian k6 untuk mensimulasikan beban trafik nyata.
